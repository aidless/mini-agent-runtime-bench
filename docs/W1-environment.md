# W1 环境（environment）：任务快照模式

> 本文档可独立评审。目标读者：未来的快照落盘者与门禁维护者。
> 一句话定位：W1 只回答“测的是同一道题吗”——把任务文本与参考答案冻结为只读快照，其他一概不做。
> 状态：pre-W1，全部取值 `TBD`，`trace_id: null`，`evidence: none`。

## 目的与范围

- 目的：为每一次评测提供不可变的任务输入基线，使“换题”与“漏题”可被发现。
- 范围内：快照字段表（见 schema）、只读冻结语义、来源追溯要求。
- 范围外：运行时行为、轨迹记录、翻转率计算（分别归 W2 / W3）；任何实时数据获取（W1 阶段不存在“活取数”）。

## Schema：任务快照字段表

快照是纯文本记录（未来落盘格式待定，候选为 JSON Lines，待定事项记 `TBD`）。每条快照一行，必须包含以下字段：

| 字段 | 类型 | 必填 | 语义 | 落盘前占位值 |
| --- | --- | --- | --- | --- |
| `snapshot_id` | string | 是 | 快照唯一标识，落盘时分配 | `TBD` |
| `task_id` | string | 是 | 任务在题库中的稳定编号 | `TBD` |
| `task_text` | string | 是 | 任务原文的完整 COPY（复制文本，不引用实现） | `TBD`（空仓阶段不得填入真实题面） |
| `gold_answer` | string | 是 | 参考答案的完整 COPY | `TBD`（空仓阶段不得填入真实答案） |
| `source_ref` | string | 是 | 题面与答案的出处（题库名与版本描述，文字描述即可） | `TBD` |
| `created_at` | string | 是 | 快照冻结时刻（ISO-8601 文字格式，落地时填写） | `TBD` |
| `trace_id` | string 或 null | 是 | 产生本快照的那次操作的追踪标识 | `null`（空仓阶段） |
| `evidence` | string | 是 | 快照生成证据的位置描述 | `none`（空仓阶段） |

约束：`task_text` 与 `gold_answer` 只允许 COPY 纯文本；任何可执行引用（模块路径、导入语句、远程地址）在 schema 层面即为非法值，门禁有权据此判无效。

## 不变量 / 反作弊（anti-gaming）

- **AG-W1-1 禁从 A 线 IMPORT**：快照只能 COPY 任务文本，不得以任何形式 IMPORT A 线模块（含 evolve / gsm8k / rag_demo 等实现，统统禁止）。<!-- allow-coupling --> 违反本条的快照视为被污染，门禁 A3 判 FAIL。
- **AG-W1-2 禁活取数**：W1 内不得发起实时网络请求、不得读取外部实时数据源；快照内容必须在冻结时刻完全确定，冻结后只读。
- **AG-W1-3 来源可溯**：每条快照必须携带 `source_ref` 与 `trace_id`；缺失任一项即不合格，不得进入 W2。
- **AG-W1-4 只读冻结**：快照写入后不可变；任何修正只能追加新版本快照（新 `snapshot_id`），禁止原地改写旧行。

## 验收标准

- [ ] 字段表逐字段可回答“缺了它会失去什么”（评审人抽查任一字段，落盘者能说清后果）。
- [ ] 四条反作弊条款逐条可判定：给定一条候选快照，能明确判合格 / 不合格并指出违反条款编号。
- [ ] 空仓诚实性：本文档与任何示例中不出现真实题面、真实答案与任何测量数字，全部占位值保持 `TBD` / `null` / `none`。
- [ ] 本文档变更后，`python tools/check_gates.py` 仍全 PASS（A2-pillars 子项覆盖字段表、反作弊、验收三要素的存在性）。

## 与其他支柱的关系

- W1 是 W2 的输入：运行时只允许消费已冻结快照，不得自行构造任务输入。
- W1 与 W3 无直接关系：翻转率重放必须引用 `snapshot_id`，但不修改快照。
