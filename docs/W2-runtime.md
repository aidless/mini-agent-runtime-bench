# W2 运行时（runtime）：最小闭环接口契约

> 本文档可独立评审。目标读者：未来的运行时实现者与轨迹审计者。
> 一句话定位：W2 只回答“测的过程可信吗”——声明最小闭环接口与轨迹日志模式，但**只声明、不实现**。
> 状态：pre-W1，全部取值 `TBD`，`trace_id: null`，`evidence: none`。本仓库不存在任何运行时实现代码。

## 目的与范围

- 目的：让任何未来的运行时实现都运行在同一张契约下，使轨迹可比、可重放、可审计。
- 范围内：闭环三接口的声明、轨迹日志字段表、不变量与反作弊、验收标准。
- 范围外：具体 agent 算法、工具实现、模型调用（永远不属于本仓库）；翻转率统计（归 W3）。

## Schema（一）：闭环三接口（声明 only）

| 接口 | 输入 | 输出 | 语义 |
| --- | --- | --- | --- |
| `reset` | 已冻结的 `snapshot_id`（见 W1） | 初始观测 | 一次运行只允许绑定一个快照，中途不得换题 |
| `step` | 当前观测 | 下一个动作与工具调用声明 | 单步语义固定，禁止在步内绕过契约去读外部实时数据 |
| `done` | 完整轨迹 | 终态 verdict（文字结论，非分数） | verdict 只记录结论原文，数值化解释一律 `TBD` |

以上为声明：签名、参数类型、错误语义在实现落地前全部记 `TBD`；任何实现必须先满足下文不变量，否则其轨迹无效。

## Schema（二）：轨迹日志字段表

每次运行必须产出一条轨迹记录，含以下字段（落盘前全部占位）：

| 字段 | 类型 | 必填 | 语义 | 落盘前占位值 |
| --- | --- | --- | --- | --- |
| `run_id` | string | 是 | 单次运行的唯一标识 | `TBD` |
| `snapshot_id` | string | 是 | 本次运行绑定的冻结快照 | `TBD` |
| `prompt_log` | string | 是 | 每次观测与动作的原文记录 | `TBD`（空仓阶段不得编造示例轨迹） |
| `tool_calls` | list | 是 | 工具调用声明序列（含名称与参数原文） | `TBD` |
| `latency_log` | string | 是 | 每步耗时记录（单位与精度待定，文字描述） | `TBD`（空仓阶段不得填入任何耗时数字） |
| `verdict` | string | 是 | 终态结论原文 | `TBD` |
| `trace_id` | string 或 null | 是 | 本次运行的追踪标识 | `null`（空仓阶段） |
| `evidence` | string | 是 | 轨迹证据的位置描述 | `none`（空仓阶段） |

## 不变量 / 反作弊（anti-gaming）

- **AG-W2-1 禁依赖 A 线实现**：运行时不得 IMPORT 或调用任何 A 线模块（含 evolve / gsm8k / rag_demo 等实现，统统禁止）。<!-- allow-coupling --> 闭环三接口必须可独立描述，描述中出现 A 线依赖即不合格。
- **AG-W2-2 单步有界**：每步必须有超时上界与步数上界，具体数值全部 `TBD`；无界运行的轨迹无效，且上界确定前不得产出任何耗时数字。
- **AG-W2-3 日志完备**：缺失任一必填字段的轨迹判无效；`prompt_log` 与 `tool_calls` 不得事后补写，只能随运行同步产生。
- **AG-W2-4 确定性重放**：同一 `snapshot_id` 加同一重放条件必须产出同一 `verdict`，否则该轨迹不得进入 W3（重放条件的定义见 W3 扰动矩阵）。

## 验收标准

- [ ] 三接口声明可回答“实现者第一步做什么”（评审人扮演实现者，能从本文档推导出待实现清单）。
- [ ] 四条反作弊条款逐条可判定：给定一条候选轨迹，能明确判有效 / 无效并指出违反条款编号。
- [ ] 空仓诚实性：本文档不出现任何实现代码、示例轨迹与耗时数字，全部占位值保持 `TBD` / `null` / `none`。
- [ ] 本文档变更后，`python tools/check_gates.py` 仍全 PASS（A2-pillars 子项覆盖字段表、反作弊、验收三要素的存在性）。

## 与其他支柱的关系
