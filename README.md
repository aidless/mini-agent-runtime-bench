# mini-agent-runtime-bench

The same frozen task can get a different verdict when a policy is run again.
This repository measures that flip on a small hand-authored set.
The figure below is from scripted policies, not from LLM agents.

judge=exact_string_match

limits: scripted policies only; they execute the frozen spec and do not read the task text; not an LLM-agent score; exact string match; one repeat; a zero flip count is stability, including stable failure; the flaky policy flips by construction; the task set is a tiny hand-authored pipeline demo.

## 愿景

为一组冻结任务提供可复算的翻转率：同一脚本策略再跑一次，结论变不变。这不是模型榜，也不测量智能体能力。

## 支柱

- **W1** 环境：`snapshots/w1/tasks.jsonl` 是手写微任务的 COPY，`snapshots/w1/manifest.json` 记下文件与逐行 sha256。策略不解析题面，只执行旁边的 `spec`。
- **W2** 运行时：`tools/runtime_loop.py` 仍提供 reset / step / done 与八字段轨迹。上面的翻转率不使用这套循环的墙钟延迟。
- **W3** 经验：翻转指重放结论与基线结论不同。本结果只冻结了一个格点：再跑一次，裁判是与金答案的逐字比对。阶段切换和独立裁判仍是 `TBD`。

## 非目标

- 不调用 LLM，不报告智能体能力、任务完成率或模型排名。
- 不把 `flaky` 的非零翻转说成采样噪声。那个策略按运行序号交替，这是定义，不是随机性。
- 不把空表 `results/flip_rate_empty.csv` 读成翻转率为零。空表是零证据；有分子分母的是 `results/flip_rate.csv`。

## 空仓契约

1. `results/flip_rate_empty.csv` 仍然只有表头。它表示尚无那张表所代表的证据，不表示测得为零。
2. `results/flip_rate.csv` 可以有数据行，但每一行必须带可回链的 `trace_ids` 和存在的 `evidence_path`。缺一则门禁失败。
3. README 里的结果数字只允许出现在 measured 块中，并且必须与重算结果逐字一致。
4. 除禁止性表述外，正文不引用 A 线实现。

## 门禁

```sh
make check
```

`make check` 离线运行，只用标准库和本机 `git`。它重算 measured 块、核对快照哈希、跑运行时自检、跑不依赖容器的运行时门，并用标准库执行 `tests/`。Docker 上的容器隔离门在守护进程或本地镜像缺失时打印 `SKIP` 和原因，不拉取镜像。`SKIP` 不是 `PASS`。设置 `REQUIRE_DOCKER=1` 时，跳过改为失败。

`python3 tools/check_gates.py` 是其中的结构、文档和诚实性门，包括空表仍仅表头，以及有数据的翻转率行必须带 trace id 与证据。

## 路线图

- 独立裁判与阶段切换格点仍未冻结。在那之前，不要把本页的翻转率推广成通用 W3 定义。
- `results/w2_runs.jsonl` 是更早的手写动作序列轨迹，含墙钟延迟，且摘要会随 `tools/` 目录变化。`make check` 不重写它。
- 容器隔离只在本机已经有 `tools/docker_sandbox.py` 里的 `DEFAULT_IMAGE` 时才会真正执行。
